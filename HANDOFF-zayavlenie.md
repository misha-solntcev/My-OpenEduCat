# Handoff: заявление о приёме — веб-форма

## Решение (19.11.2026)

- Отказались от `survey` для заявления: слишком много кода, вендоренный
  незамёрженный модуль и мост в приёмку.
- Делаем **одну страницу-веб-форму** по образцу `/anketa`.
- Модель: **`op.admission`** — форма создаёт приёмку сразу.
- Доступ: **по токену** (персональная ссылка), не публичная страница.
- Одна страница, как анкета на сайте.
- Обязательные документы: **СНИЛС**, **медицинский страховой полис**,
  **согласие на психологическое сопровождение**.
- Не требуем: паспорт, свидетельство о рождении, регистрацию.
- Дополнительно: **«Другие документы»** (несколько файлов) и комментарий.
- Форматы: PDF, JPG, PNG, HEIC; до 10 МБ на файл.
- Согласия: три подтверждения, как в бумажном заявлении.
- Выпадающий список класса не делаем.

## Сохранённые наработки по опросу

- Ветка: **`misha-solntcev/survey-zayavlenie`**, commit `c08ac31`.
- Модули: `rost_school_admission_survey`, `survey_question_type_binary`
  (вендоренный OCA PR #232 для 18.0 + `ru.po`).
- В БД `test4` опрос установлен; ответы: 5 — чистый бланк, 8 — демо
  с файлами, 11 — черновик для проверки загрузки.
- Ветку не трогать. Вернуться можно в любой момент.

## Инфраструктура

- Odoo 18, контейнер `odoo-dev-odoo-1`, БД `test4`.
- Контейнер монтирует `/home/nnm/odoo-dev/addons` как `/mnt/extra-addons`.
- Код пишется в Orca worktree. Чтобы Odoo увидел модуль, его нужно
  скопировать в `/home/nnm/odoo-dev/addons` и выдать права:
  `chmod -R a+rX /mnt/extra-addons/<module>`.
- Установка:
  `docker exec odoo-dev-odoo-1 odoo -c /etc/odoo/odoo.conf -d test4 -i <module> --stop-after-init --no-http`
- Обновление: `-u <module>`. После изменений Python/шаблонов —
  `docker restart odoo-dev-odoo-1`.
- В `/home/nnm/odoo-dev/addons` остаются **untracked** копии survey-модулей:
  они нужны работающей БД. Не удалять, пока `survey` установлен.

## Что делать в новой ветке

1. Модуль (например, `rost_school_admission_form`):
   - бинарные поля документов в `op.admission` + `_filename`:
     `snils_file`, `policy_file`, `psych_consent_file`, `other_files`
     (для «других» — несколько файлов, можно `Many2many` к `ir.attachment`);
   - `website_form_access = True` для `op.admission`; снять
     `website_form_blacklisted` с полей формы (post-init hook, как в
     `rost_school_billing/__init__.py`);
   - токен: поле на `op.admission` (или отдельная модель), генерация и
     ссылка `/zayavlenie/<token>`;
   - контроллер: `GET /zayavlenie/<token>` — проверка токена и рендер
     страницы; `POST` — приём формы с проверкой токена (свой обработчик
     или `/website/form/` + скрытое поле токена);
   - страница QWeb по образцу `/anketa` (view `website.anketa`, id 3552):
     `s_website_form`, карточки, поля, файлы, success page;
   - валидация: обязательные поля, email, размер и тип файлов; серверные
     constraints на `op.admission`;
   - успех: страница «Заявление получено», статус приёмки.
2. Проверить на телефоне: PDF, JPG, HEIC, файл больше 10 МБ, пустое
   обязательное поле.
3. Решить судьбу survey: оставить установленным для истории или удалить
   после переноса данных.

## Полезные ориентиры

- `/anketa` — QWeb view id 3552, модель `crm.lead`, `s_website_form`,
  success `/contactus-thank-you`.
- `rost_school_billing/models/crm_lead.py` — поля анкеты.
- `rost_school_billing/__init__.py` — `FORM_FIELDS` и `post_init_hook`
  (снятие `website_form_blacklisted`).
- `openeducat_admission/models/admission.py` — поля заявителя, ребёнка,
  паспорт, адреса; уже готовы для формы.
- `rost_school_billing/models/doc_engine.py` — `docxtpl` для PDF заявления
  (следующий этап после формы).

## Открытые вопросы

- Генерация и отправка токена: кнопка на приёмке/лиде, письмо, срок жизни.
- Дедупликация: одна приёмка на ребёнка; что делать при повторной отправке.
- Можно ли редактировать заявление после отправки.
- «Другие документы»: несколько файлов — `Many2many` вложений или
  отдельная модель.
